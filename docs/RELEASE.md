# AI-Dostar v1.0.0 — готовая версия

Дата: 23.09.2026 · тег `v1.0.0` · кейс HackAlem AI «Электрокомплект»: автоматизация заказов поставщикам (IEK, Systeme Electric).

## Что входит

| Требование ТЗ | Как закрыто | Проверка |
|---|---|---|
| 1. Учёт всех источников | Продажи, остатки, товар в пути (только с приходом в горизонте), кратность, рост категорий, сезонность компании, история остатков | `tests/test_acceptance.py`: изменение каждого источника меняет результат |
| 2. Сезонность и устойчивый рост | Сезонный индекс SKU → группа → компания, тренд только при устойчивом росте; опционально ML-прогноз | Труба Ø50: индекс 0.41 в феврале, 2.04 на сентябрь–октябрь |
| 3. Упущенный спрос при дефиците | Месяцы с нулевым остатком и провалом продаж восстанавливаются с учётом сезонности | Труба Ø50: +3 373 м, без компенсации заказ 14 500 вместо 16 350 |
| 4. Разовые крупные заказы | Строка накладной: медиана/MAD, доля месяца, нерегулярность | «Петля LOOP» 210 000 шт исключена, регулярные «Коробки» 36–90 тыс. — нет; вколотая строка ×50 меняет заказ < 10% |
| 5. Заказ по поставщикам с обоснованием | Обоснование каждой строки, правка менеджером с причиной, утверждение, выгрузка XLSX/CSV только утверждённого | `tests/test_product.py`, `tests/test_ui*.py` |

Сверх ТЗ:

- **ML-прогноз** (градиентный бустинг, временная валидация): ошибка на отложенных периодах ниже статистики на 16,3% (0.785 против 0.939 scaled MAE); выбирается в боковой панели.
- **Ассистент на ChatGPT**: «Спросить ассистента» — ответ на любой вопрос о заказе только по данным расчёта, каждое число сверяется; поиск обычными словами; рекомендации; объяснение строки и сводка поставщика.
- **Жизненный цикл ассортимента**: 128 угасающих позиций (38 из них расчёт рекомендовал заказать), 144 новинки, проверка кандидатов «старая модель → новая» (вердикт ИИ отменяется, если параметры в названиях различаются).
- **Проверки для жюри**: пересчёт выбранного товара с отключением каждого фактора.
- **Сравнение с текущим Excel-расчётом менеджера SE.**

Автоматической отправки заказа поставщику нет — решение за менеджером.

## Запуск

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m app.adapters.build --raw datasets    # data/clean/*.parquet, ~8 с
.venv/bin/python -m app.ml.train                         # опционально, ML-модель, ~1 мин
cp .env.example .env                                     # опционально, OPENAI_API_KEY для ассистента
.venv/bin/streamlit run app/ui/app.py
```

Windows: `.venv\Scripts\python.exe` вместо `.venv/bin/python`. Без ключа ассистент работает по правилам, объяснения — по шаблону.

## Проверено перед выпуском

- Сборка из `datasets/` с нуля: 8 таблиц, идентичны сборке из архивов партнёра.
- `pytest`: **116 passed**, без пропусков (с обученной ML-моделью). Тесты не вызывают платный API.
- Интерфейс на реальных данных, оба метода прогноза: статистика — 678 позиций к заказу / 401 критичная; ML — 574 / 400; все 6 вкладок без ошибок.
- ChatGPT (`gpt-4o-mini`) проверен живым ключом: объяснение, сводка, поиск, проверка пар, свободные вопросы.

## Ограничения данных

Нет ID клиента, цены, точных дней дефицита, сроков поставки и BOM. Остаток IEK оценочный (начало месяца минус продажи) — интерфейс требует сверки со складом. Помесячный отчёт SE расходится с накладными; спрос считается по накладным. Подробно — `docs/architecture.md` §2.
