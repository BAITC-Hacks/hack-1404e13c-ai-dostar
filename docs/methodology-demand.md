# Методика: разовые заказы и дефициты

Реализация: `app/engine/oneoffs.py`, `app/engine/demand.py`. Владелец: человек 1.
Расчёт строит регулярный спрос по накладным отдельно для каждой пары
`(supplier, sku)`. Исходные продажи сохраняются для проверки и объяснения результата.

## Разовые крупные продажи

1. Для положительных строк накладных вычисляются медиана количества `m` и
   `MAD = median(abs(qty - m))` по товару и поставщику. Возвраты не участвуют в поиске выбросов.
2. Строка становится кандидатом, если `qty > m + oneoff_k × 1.4826 × MAD`
   и её доля в сумме положительных продаж товара за месяц **строго больше 30%**.
   По умолчанию `oneoff_k = 5`. При `MAD = 0` используется порог `qty > 10 × m`.
3. Считаются различные месяцы, в которых была хотя бы одна строка объёмом
   `≥ 0.5 × qty` кандидата. Если таких месяцев меньше `oneoff_min_months`
   (по умолчанию 3), кандидат признаётся разовым. Несколько крупных строк в одном
   месяце не образуют несколько месяцев повторения.
4. Из регулярного спроса исключается только избыток `oneoff_excess_qty = qty - m`.
   В `oneoff_reason` записываются исходное и типичное количество, доля месяца и
   число месяцев повторения. Исходное `qty` и фактический расход склада сохраняются.

Товар с единственной продажей не имеет собственной истории для сравнения.
Если в его категории есть минимум 100 положительных строк, используются строки
того же поставщика и первых четырёх цифр кода 1С: порог равен `10 × P99`,
а типичный объём — `P90`. Проверки доли месяца и повторения сохраняются.
При недостаточной истории категория не используется. Это эвристика для редких
товаров; категория может содержать товары с разными объёмами отпуска.

Контроль на реальных данных: IEK `130200305_`, «Петля LOOP», 210 000 от
09.06.2025 — разовая строка; типичный объём по категории 10, исключено 209 990.
Крупные строки SE `030200192_`, «Установочная коробка», 36–90 тысяч повторяются
в разных месяцах и сохраняются в регулярном спросе. Эти проверки не зависят от
специально заданных в алгоритме кодов товаров.

`use_oneoff_filter=False` отключает исключения. При заданном `params.as_of`
анализ включает весь указанный день и не использует более поздние продажи.

## Месячный спрос и оценка дефицита

Сетка месяцев начинается с января 2025 года и заканчивается месяцем `as_of`.
Она строится для товаров с накладными в этом интервале; пропущенные месяцы имеют
нулевые продажи. Продажи и возвраты суммируются в `qty_raw` со знаком.
Базовый регулярный спрос равен `max(0, qty_raw - oneoff_excluded_qty)`.

Для оценки необходимы минимум **два полных месяца с положительным остатком
на начало месяца**. Медиана их базового регулярного спроса называется `M`.
Нулевые продажи в таких месяцах тоже входят в медиану. Для целевого месяца:

```text
expected = M × coef_month / mean(coef_available_months)
             × days_in_month_observed / days_in_calendar_month
```

Остаток `≤ 0` или отсутствующий месячный остаток считается признаком возможного
дефицита. Месяц отмечается `stockout=True`, только если этот признак есть,
базовый спрос ниже `expected`, имеется достаточно доступной истории и товар уже
появлялся в продажах либо имел положительный остаток. До первой такой активности
упущенный спрос не восстанавливается.

```text
stockout_uplift_qty = max(0, expected - base_regular) для stockout-месяца, иначе 0
qty_regular = base_regular + stockout_uplift_qty
```

Неполный текущий месяц получает ожидаемый спрос только за прошедшие дни.
Он не используется как полный месяц для оценки `M`. Продажи за весь день `as_of`
входят в результат, более поздние строки исключены. При недостаточной истории
коррекция равна нулю. `use_stockout_fix=False` отключает добавление спроса,
но сохраняет обнаруженные признаки дефицита. Коррекция уже входит в
`qty_regular`; повторно добавлять её при расчёте заказа нельзя.

## Сезонность и подключение

`build_monthly(..., params, as_of, seasonality=...)` принимает таблицу контракта
`SEASONALITY`: `supplier`, `month_num`, `coef`. Коэффициенты должны быть конечными,
положительными и уникальными для пары поставщик/месяц. Если коэффициента нет,
таблица не передана или `use_seasonality=False`, используется 1.

На момент выполнения задач человека 1 общий `pipeline.run()` вызывает функцию
без таблицы, поэтому коррекция в нём использует нейтральные коэффициенты.
Владельцу `app/pipeline.py` (человек 2) нужно передать имеющийся источник:

```python
demand_monthly = demand.build_monthly(
    sales_flagged, data["stock_monthly"], params, as_of,
    seasonality=data["seasonality"],
)
```

## Отчёт и проверка

`oneoffs.report(sales_flagged)` возвращает только разовые строки: поставщик,
SKU, дата, накладная, единица, исходное `qty`, `typical_qty`, исключённый объём
и причина. Строки упорядочены по убыванию исходного количества.

Тесты: `.venv\Scripts\python.exe -m pytest tests/test_demand.py -q` в Windows
или `.venv/bin/python -m pytest tests/test_demand.py -q` в Linux/macOS.
Синтетические проверки работают без выгрузок; проверки LOOP, коробок SE и
реального месячного ряда требуют предварительной сборки `data/clean/*.parquet`.

В данных нет ID клиента и точных периодов отсутствия товара. Единица поиска
разового заказа — строка накладной. Нулевой остаток в начале месяца не доказывает
отсутствие товара весь месяц: `stockout_uplift_qty` является оценкой, которую
менеджер должен видеть вместе с исходными продажами.
